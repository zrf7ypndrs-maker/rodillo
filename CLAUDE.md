# rodillo: instructions for Claude

Agustín's own Zwift replacement (vanilla JS web app on GitHub Pages). Private data and the training plan live in the sibling repo zrf7ypndrs-maker/rodillo-data; clone both side by side.

- **Build stamp (cache-busting id on CSS and every JS import; without it Bluefy can load new HTML with stale JS and freeze the ride screen):** `.github/workflows/pages.yml` runs tests, stamps and deploys on every push to main (Pages source = "GitHub Actions" since Nov 10). Don't run `tools/stamp.mjs` before pushing and don't resolve `?v=` conflicts by hand: take either side, the deploy re-stamps. A failing test blocks the deploy, so check `gh run list -R zrf7ypndrs-maker/rodillo -L 3` after pushing. If your run is still `queued` 5 minutes after the push (GitHub sometimes leaves runs stuck with no job), start a fresh one with `gh workflow run Deploy -R zrf7ypndrs-maker/rodillo --ref main` (works from Claude sessions; `gh run cancel` doesn't) and watch it to `completed success`. A newer run cancels older ones (`cancel-in-progress: true`). A run whose commit isn't the current head of main skips the deploy (job `current`), so a late stuck run can't put an older version live. If the fresh run also stalls, tell Agustín right away instead of reporting the change as live.
- `npm test` before pushing JS changes.
- Phone layout must never change desktop: phone styles sit behind the `PHONE_MQ` media query in js/app.js.
- Training work (plan, workouts, coaching decisions): read `rodillo-data/CLAUDE.md`, then `rodillo-data/coach/PROGRAM.md` and `coach/DAILY.md`. Log every plan change in PROGRAM.md.
- Ride history import (Strava / Garmin export, loose FIT/GPX/TCX): `js/importer.js`, UI in Settings > Sync, one commit through `GitHubSync.pushRides()`. Imported rides carry the tag `imported` plus `indoor`/`outdoor`/`mtb`/`gravel`; rides without power have `np: null` and `tssFrom: "hr"`, so never assume a summary has power.
- Workout builder (`js/builder.js`, logic in `js/mine.js`): Agustín's own workouts live in rodillo-data `workouts/mine.json` (`{ workouts, deleted }`, ids `mine-*`, newest `updatedAt` wins). Signed-in only (GitHub sign-in or token, `signedIn()` in js/app.js): signed out there is no Mine section, no New workout, no Edit a copy. They show in their own "Mine" section of the Workouts tab, never in the ERG / Slope lists. They're his, not coach workouts: the plan may use their ids, but don't edit them without asking. `daily.mjs --check` reads them.
- Coach tools here: `tools/daily.mjs` (morning brief, `--check` validator), `tools/scale.mjs` (scaled workout copies), `tools/review.mjs` (history).
- Timed workout messages: any step can carry `messages` (`at` seconds from the start, negative = before the end, or "50%"; optional `rep` number / "first" / "last" / list; `{watts}` `{ftp}` `{rep}` `{of}` `{left}` `{name}` placeholders; `{name}` = Settings > Rider > Your name, dropped cleanly when empty). Format and builder text form in js/engine/workout.js, fired by `Session._messages()`, shown as floating text over the top of the desktop ride chart (`#r-msg`, `rideMsg()` in js/app.js). Desktop only for now (Agustín wants to try it there first). Keep each message one short sentence; Block 1 workouts have a full set.
- Ride page (one completed ride: stacked charts on one time axis, intervals table, zones, best power): pure rendering in `js/ridepage.js` (tested in test/ridepage.mjs), wiring in js/app.js (`openRide(id)`, `loadRideDoc`, `rideAction`). Opens from the done hero, Training rows and ridden Calendar days. Loads this device's recording first, then the cached copy (IndexedDB store `docs`, newest 40), then `rides/YYYY/<id>.json` from rodillo-data. Interval timing comes from the `seg` stream `buildRide()` writes since Nov 11; older synced rides fall back to the workout's own timing.
- End of ride (Nov 12, UX roadmap item 2): no summary screen. `endSession()` saves the ride, then `openDone(ride)` opens the ride page with a green done bar (`doneBarHtml()` in js/ridepage.js): headline "Done. 4 of 5 reps on target.", effort note, "vs" the last ride of the same workout (`lastSameWorkout()`, `vsLastTime()`; avg HR only at the same FTP), "Stop and save your Garmin", sync status, FTP prompt, Done / Export .FIT / Discard. Sync starts right away (`syncRide()`). Discard deletes locally and, if it already synced, removes the file + index entry from rodillo-data in one commit (`GitHubSync.deleteRide()`); failed deletes queue in localStorage `rodillo.pendingDeletes` and retry in `syncPending()`.
- Reps are scored against the plan (Nov 12, Agustín): samples record `plan` (workout watts at effort 100%) and `eff` (effort multiplier when not 1); `intervalResults()` uses `plan` for target and %, and sets `effort` on a rep ridden at a changed effort. Older rides (no `plan`) keep their old scores. `summary.compliance` counts only reps when the workout has them (not the opener).
- Ramp test (`workouts/ramp-test.json`): Zwift protocol, 1-min steps from 100 W, +20 W/min, steps marked `untilFail` so the ramp has no top (engine adds steps; ends when 3 s power < 85% of target for 8 s, the ERG guard kicks in, or he stops pedalling for 2 s at >= 70% FTP; no auto-pause in that part or for 30 s after the end; hold B ends the test, not the ride). Coach cues and the result live in `js/testcoach.js` (pure, tested); `takeover()` in js/app.js grows the interval card to full screen for hard steps (>= FTP) and the result. Desktop only, like messages. FTP = 75% of best minute.
- Gearing and trainer range (Nov 11; gearing UI moved to the Garage Nov 12): drivetrain presets (grouped, ids never renamed) + custom chainrings/cogs/wheel in `js/engine/drivetrain.js` (`checkSpec`, `presetFor`, `resolveDrivetrain`; settings `drivetrain` = preset id or `custom` + `customDrivetrain`). Trainer models and their grade range (maker's spec) in `js/engine/trainers.js`; settings `trainerModel`, `maxSendGrade`, `minSendGrade`. With no model chosen, the first trainer connection picks it from the Bluetooth name (`detectTrainer()` in js/app.js). Details: project doc `claude/rodillo-gearing-trainer.md`.
- Virtual shifting in the trainer (Nov 11): `js/ble/zwifthub.js` speaks the Zwift trainer protocol (RideOn handshake on 0xFC82 or 00000001-19ca-..., HubCommand 0x04 with SimulationParam grade + PhysicalParam gear ratio, riding data 0x03; bytes checked against Makinolo's KICKR CORE capture). `Trainer.setup()` tries it after FTMS; no answer in 3 s = FTMS as before. Slope then sends road grade + `ratio * wheelCirc / 2.105`, no feedforward or trim; ERG stays FTMS. Setting `trainerShifting` ('auto' | 'app'), Settings > Trainer. Rides record `zp` (1 = trainer shifting). Reverse-engineered, not a spec: if Zwift changes it, 'app' is the escape hatch. Details: project doc `claude/rodillo-zwift-protocol.md`.
- Bike garage (Nov 12, Agustín): a centered popup (`#garage`, still a `.panel` so scrim / Close / Esc / B / the pause screen work; CSS `#garage.panel` centers it) behind the top-bar Garage button, which shows the Free ride bicycle (`BIKE_ICO`, pedals on hover). Each bike is a square tile: built-ins show Agustín's photos (background-free cutouts, 640 px WebP) kept in the PRIVATE repo rodillo-data `garage/<model>.webp` so Canyon's photos stay off this public site; `bikePhoto()` loads them through the sign-in (`gh.api('/contents/garage/...')`) and caches them as data URLs in localStorage `rodillo.garagePhotos`. Never commit those photos to this repo. No photo (custom bikes, signed out, not loaded yet): just the name and gears/weight, centered (Agustín dropped the hand-drawn bikes; `artFor()` returns ''), plus a dashed "+" tile for Custom bike and faded "Add it back" tiles for removed built-ins. `renderGarage(view)` in js/app.js has three views: **list** (the tiles; tap = ride it; "See details" under each; "Riding" corner badge), **details** (read-only: gears, rings, cogs, easiest/hardest, wheel, shifting, weight, source; Ride this bike, Custom bike from this one, Remove) and **custom** (name, gearing, weight; "Save as new bike" adds and selects it, Cancel discards). Saved bikes are never edited in place. The gearing and weight editors (`fillDrivetrain`, `editDrivetrain`, `fillStyle`, `fillBike`, `pickBike`, `editBike`) work on `draft`, never on settings. Settings has no Gearing tab and no bike in Rider. Engine `js/engine/garage.js`; settings `garage` (list, or `null` = the built-in two) and `bike` (id in use or ''). Picking a bike copies its `drivetrain`/`customDrivetrain`/`shiftStyle`/`bikeKg`/`bikeSpec` into settings, so the engine is unchanged. Gearing menu: Gears "a x b" (1x9 to 2x13, or Zwift virtual 24), chainring teeth (big + small on 2x), smallest and largest cog from dropdowns (`COG_MINS`, `COG_MAXES`); cogs in between from `cassette()` (a real cassette when one matches, else growing steps); wheel inferred by `wheelFor()`; `simpleSpec()` + `presetFor()`. Shifting (`shiftStyle`, normalised by `shiftStyleFor(style, oneX)`): 2x = 'sram' (left easier, right harder, both = front) or 'shimano' (left buttons = front); 1x = 'right' or 'left', the hood the shifter is on (that side's shift-up / paddle harder, shift-down easier; the other side doesn't shift). Lux Trail = right, Aeroad = shimano. `reconcileSettings()` keeps `shiftStyle` equal to the bike in use's. Built-in: Canyon Lux Trail CF 7 (Eagle 90 Transmission 32T + 10-52, 29 x 2.4, 13.1 kg = 12.8 claimed M + XT pedals) and Canyon Aeroad CF SLX 7 Di2 (105 Di2 52/36 + 11-34, 8.1 kg = 7.84 claimed M + road pedals). `BIKE_MODELS` ids never renamed. Rides record `summary.bike` (name). `[data-open-garage]` links open it. **Bike check (Nov 12, Agustín):** starting a free ride or any workout with slope steps (`isSim(w)`) first opens `confirmBike()`: the in-app modal (`ask()` with `body`, `nav`, `wide`) titled "Riding the <bike>?" with a tile per garage bike (selected one inverted); tap or controller left/right picks another, "Ride this bike" applies it (`selectBike`) and starts, Cancel / B doesn't start. ERG workouts skip it; an empty garage skips it. The pause / ready screen has no Garage button (removed at Agustín's request): Connections, Controls, Settings only. Details: project doc `claude/rodillo-bike-garage.md`.
- **Bike vs gearing split (Nov 12, Agustín: "bike could just mean weight and wheel size"; the user may switch gearing mid-ride).** A garage bike = `{ id, name, model?, bikeKg, bikeSpec, wheel }`; picking it sets `bikeKg`, `bikeSpec`, `wheelCirc` only. Gearing is its own choice (settings `drivetrain` + `customDrivetrain` + `shiftStyle`), in the Garage popup's second tab (Nov 12, 4:22 pm: tabs **Bikes | Gearing**, `#gar-tabs`, `setGarTab()`, `openGarage(tab)`; the top-bar bike opens Bikes, `openGearing()` = Gearing tab; switching tabs discards a half-made bike or gearing; `#gearing-form` with `renderGearing()`, `gearListHtml()`, `gearNewHtml()`): tiles for the built-in gearings (`BUILTIN_GEARINGS`: the two Canyons' stock drivetrains + Zwift virtual 24, ids never renamed) and the rider's own (settings `gearings`, max 12, Remove), "+ New gearing" (the simple editor), an "All gearings" select with every preset (`gearOptions()`; presets get the brand's style on 2x, the current side on 1x: `presetStyle()`), and the Shifting select for the gearing in use (an own gearing keeps its style). The gearing in use is whichever matches `drivetrain` (`currentGearing()`); no extra key. Opens from the pause screen (`#pz-gearing`, 4th button), `[data-open-gearing]` links (Controls panel, Garage help, Rider help). Slope rides record `summary.gearing` (the last one used). Engine in js/engine/garage.js, tests "gearings" and "garage moved to the bike / gearing split". Project doc: `claude/rodillo-bike-gearing-split.md`. Where older bullets above say a bike carries gearing or shifting, this one wins.
